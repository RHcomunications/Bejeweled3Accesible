# AGENTS.md

Instrucciones para asistentes de código que trabajen en este repositorio.

## Reglas de oro

- **Documentación siempre al día (directiva innegociable):** en CUALQUIER cambio de código, fix o nueva funcionalidad se debe actualizar `context.md` (informe técnico/arquitectura/anecdotario) y la documentación pertinente (`README.html`, y esta misma `AGENTS.md` si afecta convenciones de build/release/tests). No entregar un cambio sin su correspondiente actualización de docs.
- **No borrar nunca más sonidos, música ni ficheros del proyecto original.** Los assets son imprescindibles; cualquier limpieza debe confirmarse siempre con el usuario.
- El proyecto target es .NET Framework 4.5 (C# 5), mono-proyecto `src/Bejeweled3Accessible.csproj`.
- Dos únicos builds soportados: `Debug` y `Release` (MSBuild del Framework).
- El juego se ejecuta desde `bin\Debug\` o `bin\Release\`; nunca mover el exe fuera de su carpeta.
- `audio.pac` es **el** paquete de audio para distribución: se genera con `Bejeweled3Accessible.exe --pack-audio` (y se puede regenerar cuando cambien los assets). Pesaba ~160 MB porque empaquetaba también los MP3 de las pistas 01-23, que en realidad son solo offsets del módulo `Bejeweled3_suite.mo3` (la música real del juego, cargada una sola vez). Desde v2026.08.18.0 el empaquetador (`PacPacker`) las excluye, así que el PAC queda en **~14 MB** (SFX + módulo `.mo3` + ambientales 24-29). Los MP3 de pistas 01-23 siguen en `music/` como assets originales, pero no se empaquetan ni se usan en runtime.
- Las imágenes del juego (gemas, logo heatwave) **no van en el PAC**: se cargan en caliente desde `sounds\images\` junto al exe. Por eso el zip de release DEBE incluir esa carpeta.
- **Sonidos originales (sin procesar):** los SFX en `sounds/*.ogg` se mantienen **tal cual vienen del juego original** (44.1 kHz, sin high-shelf ni upsampling). La salida de BASS va a 44.1 kHz nativos (`BASS_Init(-1, 44100, ...)`) para no resamplear las fuentes. **Audio espacial = paneo estéreo simple por columna** (clásico Bejeweled, L/R según la columna A..H vía `BASS_ATTRIB_PAN`); NO hay sala/rebotes ni EQ de profundidad. La clase `GridSpatializer` (render binaural de "objeto en sala") se **eliminó** por agresiva: los SFX ahora solo se panearan y la música suena centrada y plana. El flag `SoundEngine.BinauralEnabled` (toggle en Opciones) controla únicamente si el paneo por columna está activo. El pitch del `gem_hit` en cascadas/Relámpago sube un semitono por nivel usando las variantes pre-renderizadas con rubberband `gem_hit_p0.ogg`..`gem_hit_p12.ogg` (0..12 semitonos): conservan el timbre original **sin el lowpass que introduce BASS FX** al hacer time-stretch, por eso ya NO se usa `BASS_FX_TempoCreate` para el pitch. `bass_fx.dll` (x64) y `bass_fx32.dll` (x86) deben seguir junto al exe en `bin\Debug` y en el zip de release por si se reactiva en el futuro, pero el pitch de cascada no los usa. No borrar ni regenerar esas variantes sin re-aplicar rubberband.
- **Versiones y hotfixes:** si el usuario indica «hotfix», la release se etiqueta con el **mismo día** y se incrementa el último componente (`v2026.08.10.1`, `v2026.08.10.2`, ...). Si no hay hotfix y pasa el día, la release se etiqueta con el **día siguiente** (`v2026.08.11.0`, ...). Nunca inventar una fecha distinta ni saltarse el día.

## Build y tests

- Compilar: `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe src\Bejeweled3Accessible.csproj /t:Build /p:Configuration=Debug` (y `Release`).
- **NUNCA usar `/t:Rebuild`**: el `.csproj` copia los assets (`audio.pac`, `bass*.dll`, `libopenmpt.dll`, `openmpt-*.dll`, `nvdaControllerClient32.dll`, `README.html`) desde `..\bin\Debug\...` vía `<Content Include="..\bin\Debug\...">`; `Rebuild` ejecuta `Clean` y borra esos assets de `bin\Debug` → `MSB3030` (`No se pudo copiar el archivo "bin\Debug\audio.pac" porque no se encontró`). Para forzar recompilación completa se hace `touch` de los `.cs` (o se borra solo el exe/pdb), **nunca** se limpian los assets. Los assets de `bin\Debug` también son la fuente de los de `bin\Release`, así que si se borran hay que restaurarlos desde `bin\Release`.
- **Canales de actualización (dev/stable):** la build `Debug` es el canal **dev** que corre en la máquina del usuario y se mantiene al día **reconstruyendo `bin\Debug` en el workspace** (NO se publica en el repo: jamás subir un zip de Debug a GitHub). La build `Release` es el canal **stable**, se publica en GitHub y es lo que recibe el público. El auto-updater distingue el canal en tiempo de compilación (`#if DEBUG` en `AutoUpdater.IsDevBuild`): en `Debug` no consulta GitHub (se actualiza localmente al reconstruir); en `Release` consulta la última release estable. Por tanto, **tras cada cambio de código reconstruir también la configuración `Debug`** para que la máquina del usuario quede al día.
- Tests: compilar `src\Bejeweled3AccessibleTests.csproj` y ejecutar `bin\Debug\Bejeweled3AccessibleTests.exe` → deben pasar **144/144** (con `--no-audio`: 129 ejecutados + 15 tests de sonido real omitidos, 0 fallos).
- Los tests tardan ~20 s; no se necesitan para cambios triviales pero sí para los que tocan `Board`, motor de audio o lógica de juego.
- Para no interferir con el usuario: `Bejeweled3AccessibleTests.exe --no-audio` omite las pruebas que reproducen sonido (las de prefijo `Sound:`) y termina en segundos; se usa en comprobaciones intermedias y deja la suite completa (con audio) para la versión que se publica.

## Release

- Publicar: `gh release create v2026.08.10.X --notes-file <notas> --title "Bejeweled 3 Accesible v2026.08.10.X"` y subir el zip con `gh release upload`.
- El zip se construye con: exe y PDB de `bin\Release\`, `bass.dll`, `bass_fx.dll` (x64), `nvdaControllerClient32.dll` (de `bin\Debug`), `mscorlib.dll` + `norm*.nlp` + `es\` (directo de `bin\Release`), `README.html`, `audio.pac` (el actual de la release anterior o regenerado con `--pack-audio`) y **`sounds\images\` completa** (gemas 600/768/1200 + NonResize).
- **El zip de release NO debe incluir los `sounds/*.ogg` (salvo la carpeta `sounds\images\`) ni la carpeta `music\`:** todos los SFX y la música ya van empaquetados en `audio.pac`, y el exe los carga de ahí (`SoundEngine.LoadAudioBytes` consulta `audio.pac` primero). Por tanto, antes de empaquetar, dejar `bin\Release` sin `sounds/*.ogg` ni `music\` (solo `sounds\images\` + `audio.pac`). El canal `Debug` sí mantiene `sounds\` y `music\` completos como respaldo para desarrollo, pero el `Release` (stable) se publica solo con `audio.pac` + `sounds\images\`.
- **Nombre del zip OBLIGATORIO:** `Bejeweled3Accesible-<version>.zip` (una sola 'c', exactamente igual que la constante `AutoUpdater.ZipAssetPrefix`). REGLA CRÍTICA DE CEROS: `Version.ToString()` **no rellena con ceros**, así que la versión va SIN ceros a la izquierda: `Bejeweled3Accesible-2026.8.28.2.zip` (NUNCA `2026.08.28.2`). Si el nombre no coincide (doble 'c' O ceros de más/menos), el auto-updater arma una URL distinta y falla con **404** al descargar. Siempre verificar que el asset subido coincide con `AutoUpdater.BuildZipAssetName(tag)` (que ya produce el formato sin ceros).
- **Después de publicar una release, limpiar `C:\Users\artik\AppData\Local\Temp\opencode`** (zips de descarga, staging y capturas intermedias) para no dejar espacio ocupado en el disco.
- La versión se sube en 3 sitios a la vez: `src\Properties\AssemblyInfo.cs`, los textos `LoadingTitle` y `AppTitle` de `src\Engine\Localization.cs`, y la línea de versión + changelog de `README.html`.
